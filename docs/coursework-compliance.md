# Соответствие требованиям курсовой работы

## Тема проекта

CarGO — веб-приложение для управления автопарком и оформления аренды автомобилей по периодам.

Система позволяет клиентам искать доступные автомобили на заданные даты и оформлять заказы на аренду, а менеджерам автопарка (FLEET_MANAGER) управлять автомобилями, тарифами, окнами технического обслуживания и переводить заказы по этапам жизненного цикла.

| Требование | Где реализовано | Endpoint / сценарий |
| --- | --- | --- |

Менеджер управляет каталогом автомобилей, тарифами, техническим обслуживанием и переводит заказы по жизненному циклу (`ISSUED`, `COMPLETED`). |
| **Минимум 5 сущностей и связи между ними** | Сущности `Car`, `Tariff`, `ClientProfile`, `RentalOrder`, `MaintenanceWindow`, `RentalStatusHistory` | Спроектирована реляционная БД с нетривиальными связями (One-To-Many между машиной и заказами/окнами ТО, Many-To-One между заказом и клиентом/тарифом). ER-модель подробно описана в отчете. |
| **Транзакционный сценарий** | Оформление заказа клиентом с защитой от пересечения дат и double-booking | Метод создания аренды выполняет транзакционную проверку на отсутствие пересечений с другими заказами или окнами ТО с использованием пессимистической блокировки на уровне СУБД (`SELECT ... FOR UPDATE`). |
| **Кэшируемый сценарий** | Получение списка активных тарифов для расчета стоимости | Метод `TariffService.getActiveTariffs()` кэшируется через Redis с помощью аннотации `@Cacheable`. Кэш автоматически сбрасывается с помощью `@CacheEvict` при добавлении или изменении тарифов менеджером. |
| **Фоновый сценарий** | Автоматическая проверка просроченных броней и автозавершение аренд | Фоновый планировщик `@Scheduled` в классе `RentalStatusScheduler` с определенной периодичностью проверяет активные аренды, фактическое время возврата которых просрочено, или автоматически закрывает завершенные заказы. |

| **Тестируемость** | Тестирование бэкенда через Testcontainers PostgreSQL | Написаны интеграционные тесты с использованием реальной СУБД PostgreSQL, запускаемой в Docker-контейнере через Testcontainers, для проверки логики непересекающихся бронирований. |

| **Frontend-покрытие** | Одностраничное приложение (SPA) на Vue 3 + TypeScript | Реализованы полноценные интерфейсы для клиента (каталог машин, форма бронирования, список заказов) и менеджера (дашборд аналитики, таблицы автопарка и тарифов, управление обслуживанием). |

## Ключевые пользовательские сценарии

### Клиент (CLIENT)

1. **Регистрация и вход**: создание аккаунта клиента, аутентификация с получением JWT-токена.
2. **Поиск автомобилей**: указание дат аренды (начало/конец), получение списка доступных машин и итоговой стоимости аренды для каждого класса.
3. **Бронирование автомобиля**: выбор автомобиля, тарифа, заполнение анкеты (паспорт, права) и создание заказа в статусе ожидания.
4. **Мои аренды**: просмотр истории заказов, текущих активных аренд и отслеживание их статусов в реальном времени.

**Frontend-страницы**:
- `LoginView.vue` — страница входа и регистрации.
- `ClientCatalogView.vue` — поиск машин по датам и просмотр доступных вариантов.
- `CarDetailsView.vue` — просмотр карточки машины и форма подтверждения аренды.
- `ClientOrdersView.vue` — список личных заказов и их статусов.

---

### Менеджер автопарка (FLEET_MANAGER)

1. **Панель аналитики**: просмотр ключевых метрик автопарка (количество машин на линии, активные заказы, запланированные ТО).
2. **Управление автопарком**: добавление новых автомобилей (VIN, регистрационный знак, класс), редактирование параметров и вывод из эксплуатации.
3. **Планирование обслуживания**: создание окон технического обслуживания (MaintenanceWindow) для конкретной машины на выбранные даты (с автоматической блокировкой бронирования).
4. **Управление заказами**: подтверждение заказов клиентов, выдача ключей с переводом заказа в статус активной аренды (`ISSUED`), прием автомобиля с фиксацией времени возврата и переводом в `COMPLETED`.

**Frontend-страницы**:
- `ManagerDashboardView.vue` — главная панель аналитики и метрик.
- `ManagerFleetView.vue` — управление списком транспортных средств автопарка.
- `CarEditView.vue` — форма редактирования параметров и планирования ТО.
- `ManagerOrdersView.vue` — управление активными заказами клиентов.
- `ManagerUsersView.vue` — просмотр зарегистрированных пользователей.

## Транзакционные гарантии и защита от конфликтов

| Сценарий | Возможный риск / коллизия | Способ защиты и решения |
| --- | --- | --- |
| **Оформление аренды** | Два клиента одновременно пытаются забронировать последний свободный автомобиль на пересекающиеся даты. | Метод создания заказа открывает транзакцию, накладывает блокировку на запись автомобиля (`SELECT ... FOR UPDATE`), повторно проверяет отсутствие пересечений дат в базе данных и только после этого сохраняет заказ. Любой параллельный запрос ожидает завершения транзакции и получает ошибку коллизии. |
| **Создание окна обслуживания** | Менеджер создает окно ТО на даты, на которые клиент в этот же момент оформляет аренду. | Использование аналогичной транзакционной проверки и блокировки автомобиля перед записью `MaintenanceWindow` в СУБД, исключающей состояние гонки (Race Condition). |

## Запуск проекта одной командой

```bash
docker compose up --build
```
команда автоматически поднимет PostgreSQL, Redis, бэкенд и фронтенд-сервис Nginx, настроив сетевое взаимодействие между ними.
